## Operating principles

- **System proposes. Owner commands. Automation executes only after approval.**
- One public name, one definition and one canonical engineering source.
- Repository contents establish source history, not production health.
- Runtime, customer, revenue, investment, award, partnership and external-recognition claims require separate evidence.
- Consequential changes remain subject to explicit owner approval.

## Evidence language

- **BUILT** — supported by repository or source history.
- **READY** — prepared for the next controlled step.
- **VERIFIED** — supported by direct evidence from the relevant runtime, provider or independent source.
- **COMMERCIAL** — supported by business and transaction evidence.
- **RECOGNIZED** — supported by independent external recognition.

Plans, prototypes, source code and historical statements are not presented as proof of live operation.

## External ecosystem boundary

Bulgarian research centres, universities, public infrastructure providers and private engineering companies are independent organisations. Their ownership, staff, facilities, funding and achievements are not part of this portfolio unless a specific relationship or contribution is documented.

Potential integration opportunities are not represented as existing partnerships.

## Delivery rule

**GitHub → validation → approved delivery route → smoke/health checks → retained evidence**

No unverified deployment or production claim is accepted.
